1. Der 4-Stufen Datenfluss (Architektur)

PHASE 1 (P=0)

PII-Maskierung

Regex + spaCy NER schwärzen Namen, Orte, E-Mails und Kontonummern zu neutralen Tokens wie [[NAME_PER_1]].

Input: "Herr Schmidt aus München"
→ [[NAME_PER_1]] aus [[NAME_LOC_1]]
PHASE 2 (P=10)

Model Router Gate

Entscheidet anhand von PII-Status, Intent und Komplexität. Kritische PII sperrt die Cloud. Injiziert modellspezifische Temp & Top-P.

Prüfung: Keine kritische PII.
Task: Coding > 120 W → Claude 4.5
PHASE 3 (EXEC)

Inferenz & Execution

Request geht via Tailscale an LM Studio auf die Workstation oder an die Cloud. Die Cloud sieht nur Platzhalter, keine echten Daten!

Node: Workstation LAN (:1234)
Kosten: 0 Cloud-Credits
PHASE 4 (OUTLET)

Re-Hydrierung

Das PII-Outlet ersetzt alle Tokens wieder durch die Originaldaten. Unter pii_audit wird ein lückenloses Audit-Log abgelegt.

Output: "Guten Tag Herr Schmidt!"
Status: Deanonymisiert ✓
